# Безопасность бэкенда Polaris

Составлено 25.07.2026 по итогам аудита. Описывает, что уже закрыто в коде и
что осталось решить Алексу (сознательно НЕ сделано без его решения).

## Что было

AI-эндпоинты Cosmo (`POST /v1/ai/chat`, `POST /v1/ai/trade-comment`) были
открыты всему интернету:

- ни ключа, ни лимита частоты — любой мог дёргать их бесконечно;
- `Access-Control-Allow-Origin: *` — любой сайт мог обращаться к ним из
  браузера пользователя;
- у стримингового чата не был задан `max_tokens` (у `commentOnTrade` — 120),
  то есть один запрос мог сжечь сколько угодно токенов;
- адрес сервера лежит в APK **открытым текстом** (`app/lib/services/api.dart`,
  `PolarisApiConfig.defaultBaseUrl`) — найти его тривиально, распаковав APK.

Стоимость риска: Cosmo работает на **бесплатной квоте Groq**. Её выработка
означает «наставник молчит у всех игроков», а не счёт к оплате — но продукт
теряет главную фичу.

## Что закрыто в этом коммите

| Мера | Где | Значение по умолчанию | Переменная окружения |
|---|---|---|---|
| Лимит частоты для AI по IP | `src/ratelimit.js`, `src/server.js` | 20 запросов / 5 мин | `POLARIS_AI_LIMIT`, `POLARIS_AI_WINDOW_MS` |
| Лимит частоты для рыночных данных | там же | 300 запросов / 1 мин | `POLARIS_MARKET_LIMIT`, `POLARIS_MARKET_WINDOW_MS` |
| CORS по списку | `src/server.js` | `http://localhost:3000`, `http://127.0.0.1:3000` | `POLARIS_ALLOWED_ORIGINS` (через запятую) |
| Потолок ответа модели | `src/ai.js` | `max_tokens: 700` | — |
| Потолок входа | `src/ai.js` | 20 сообщений × 4000 символов | — |
| Доверие к `X-Forwarded-For` | `src/ratelimit.js` | выключено | `TRUST_PROXY=1` |

Важные оговорки, чтобы не было ложного чувства защищённости:

- счётчики лимита живут **в памяти процесса**: рестарт их обнуляет, между
  несколькими инстансами они не делятся;
- за одним NAT/оператором сидит много людей с одним IP — поэтому лимиты
  щедрые, они отсекают скрипт, а не человека;
- IP подделывается заголовком, если сервер стоит за прокси. Включайте
  `TRUST_PROXY=1` **только** когда перед сервером действительно есть обратный
  прокси, который сам перезаписывает `X-Forwarded-For`;
- мобильное приложение не шлёт заголовок `Origin`, поэтому CORS-список его
  никак не задевает. Ограничение работает только против чужих **сайтов**.

## Что осталось (решение Алекса, НЕ сделано намеренно)

1. **Ключ приложения.** Клиент шлёт `X-Polaris-Key`, сервер сверяет с
   `POLARIS_APP_KEY`. Стоит 20 строк, но ключ в APK всё равно вскрывается —
   это фильтр от случайного трафика, не защита.
2. **Аттестация устройства** (Play Integrity / App Attest) — настоящий ответ
   на «как отличить наше приложение от скрипта». Требует Google-проекта и
   серверной проверки токена.
3. **Учётные записи и квота на игрока** — если появится вход в аккаунт;
   тогда же лимит переедет из памяти в БД (или Redis).
4. **Перенос лимита на уровень прокси** (nginx `limit_req`) — переживает
   рестарт приложения и дешевле по CPU.
5. **Живой бэкенд — это n8n**, а не этот Node-сервер (см. ниже). Меры выше
   нужно продублировать в воркфлоу или закрыть их на уровне nginx.

## Где живёт бой

Приложение по умолчанию ходит на `https://178-105-123-85.nip.io/webhook/polaris`
— это **воркфлоу n8n** на Hetzner. Node-сервер в `server/` — резерв с тем же
контрактом v1. Правки в `server/src/` **не попадают в бой автоматически**:
их нужно перенести в воркфлоу (папка `server/n8n/`, трогать её отдельной
задачей — там лежит подготовленный к заливке патч и снимки для отката).
